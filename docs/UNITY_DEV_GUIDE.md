## Установка Unity 6.3 LTS (первый раз)

Unity Hub заблокирован в РФ/РБ по IP. Установка:

1. **Включи VPN** (любой, из твоего региона). Понадобится только для этих трёх шагов.
2. Качай Unity Hub: https://unity.com/download
3. Запусти Hub, выбери **Installs** → **Add** → **Unity 6.3 LTS** (версия `6000.3.0f1`).
4. В компонентах отметь:
   - **Windows Build Support** (IL2CPP, Mono)
   - **Linux Build Support** (Mono, Server)
   - **Microsoft Visual Studio Community 2022** (если нет своей IDE)
5. Дождись установки (~10 минут). После установки редактор работает **без** VPN — блокировка только на Unity Hub и загрузке первого раза.
6. Активация лицензии Personal:
   - Hub → Settings → Licenses → **Activate New License** → **Personal** (бесплатно до $200k дохода/год)
   - Нужен логин в Unity ID (регистрация там же). VPN на этом шаге **включён**.

После активации Hub и редактор работают без VPN. Лицензия проверяется раз в 30 дней — если VPN снова понадобится, включишь.

## Что делают скрипты

### `CorraInput.cs`
Единая точка ввода с геймпада и клавиатуры. Создаёт действия (`InputAction`) в коде, без ассета `.inputactions`, чтобы всё было видно в git-диффе.

**Привязки по умолчанию:**
- **Движение:** левый стик, крестовина, A/D, стрелки
- **Прыжок (A):** buttonSouth геймпада, пробел
- **Бег (B):** buttonEast, Left Shift
- **Рывок (Y):** buttonNorth, Left Ctrl
- **Лай (X):** buttonWest, E
- **Пауза:** Start, Escape

Другие скрипты читают свойства типа `_input.JumpPressed`, `_input.Move` и не знают, какое устройство использовано.

### `CorraController.cs`
Движение Корры: шаг, бег, рывок, прыжок. Всё из спеки (раздел 4):
- Скорости: 3/6/10 м/с (шаг/бег/рывок).
- Рывок на 1,5 с, перезарядка 3 с.
- Прыжок с переменной высотой (отпустил кнопку раньше — ниже), coyote time 0,1 с, буфер нажатия 0,1 с.
- Свойство `Stamina` (0..1) для полоски выносливости в HUD.
- Методы `Teleport` (загрузка из сохранения), `RefillStamina` (какашка кота).

Все числа в инспекторе — можешь крутить.

Использует `CharacterController` Unity — компонент для персонажей-капсул. Не физический Rigidbody, так что столкновения обрабатываются вручную.

## Первый шаг: прототип движения

**Задача:** капсула-Корра бегает и прыгает по серым кубам. Окружение, анимация, модель пока не нужны — проверяем ощущения.

### 1. Создай сцену
**Window → General → Project**. В панели Project:
- ПКМ в `Assets/Scenes` → **Create → Scene**
- Назови `YardLevel.unity`
- Двойной клик — сцена откроется.

Unity создаёт в любой сцене `Main Camera` и `Directional Light` (солнце) автоматически. Оставь как есть.

### 2. Создай землю (платформа)
**Hierarchy (левая панель) → ПКМ → 3D Object → Cube**. Назови `Ground`.  
**Inspector (правая панель):**
- Position: (0, 0, 0)
- Scale: (50, 1, 1) — длинная платформа по X

### 3. Создай Корру (капсула)
**Hierarchy → ПКМ → 3D Object → Capsule**. Назови `Corra`.  
**Inspector:**
- Position: (0, 2, 0) — над землёй
- Rotation: (0, 90, 90) — капсула лёжа, голова вправо
- Scale: (0.6, 0.5, 0.6) — низкая и широкая, как корги

**Добавь компоненты:**
- Inspector → **Add Component** → `Character Controller`
  - Center: (0, 0, 0)
  - Radius: 0.5
  - Height: 1.0
  - Skin Width: 0.08
- **Add Component** → `CorraInput` (начни печатать, Unity найдёт)
- **Add Component** → `CorraController`

В инспекторе CorraController видны поля из скрипта: `walkSpeed`, `jumpHeight` и так далее. Значения по умолчанию уже стоят из кода — можешь крутить.

### 4. Настрой камеру
Выбери `Main Camera` в Hierarchy.  
**Inspector → Transform:**
- Position: (0, 2, -10) — сбоку сзади, на высоте Корры
- Rotation: (0, 0, 0) — смотрит вперёд вдоль Z

**Camera компонент:**
- Projection: Orthographic
- Size: 5 — захват по вертикали

Позже привяжем камеру к Корре скриптом, чтобы следовала.

### 5. Запусти
Нажми **▶ Play** сверху над сценой (или Ctrl+P).

Управление:
- A/D или левый стик — движение
- Пробел или A (геймпад) — прыжок
- Shift или B — бег
- Ctrl или Y — рывок (полоска пока не показана, но работает: при рывке Корра разгоняется до 10 м/с)

Капсула прыгает, бегает. Прыжок ниже, если отпустить кнопку рано. Coyote time позволяет прыгнуть чуть после схода с края.

Чтобы остановить — снова **▶ Stop** или Ctrl+P.

## Модель Корры — готова и лежит в проекте

**Файл:** `Assets/Models/Corra/corgi.glb` (492 КБ)

- **Название:** Dog corgi animated
- **Автор:** zinaida — https://sketchfab.com/zinaida
- **Лицензия:** CC BY 4.0. При публикации игры нужно указать автора — текст готов в `Assets/Models/Corra/ATTRIBUTION.md`.

Что я в ней проверил, разобрав контейнер скриптом (Unity для этого не нужен):

- 6 224 треугольника, 1 материал, текстура 1024×1024 внутри файла
- скелет из 22 костей, корень — `Bone_20`, голова на `Bone.003_4`
- три клипа: `Run` 1.17 с, `Jump` 0.92 с, `Sitting` 2.71 с

Отдельных клипов Idle и Walk в модели нет. Поэтому стойка — это первый кадр `Sitting`, ходьба — тот же `Run` с пониженной скоростью клипа. Лай пока изображается через `Jump`.

**Почему GLB, а не FBX.** Модель на Sketchfab отдаётся в `.blend`, `.usdz`, `.gltf` и `.glb`, FBX там нет. GLB — один файл, внутри всё сразу: меш, скелет, анимации, текстура. Unity читает его через официальный пакет `com.unity.cloud.gltfast` (добавлен в `Packages/manifest.json`). `.blend` не подходит: Unity открывает его, только если на машине стоит Blender, и тихо конвертирует в FBX.

Кот уже лежит в `Assets/Models/Cat/Cat.fbx` — Quaternius Vol.2, CC0, 2 анимации (Idle, Walk). Перекрашивается в рыжего через Material.

## Как собрать Корру в префаб (один клик)

После того как откроешь проект первый раз (Unity сама импортирует `corgi.glb` и поставит пакеты):

1. Проверь импорт: кликни `corgi.glb` в Project → в инспекторе вкладка **Animation** → должно быть три клипа `Run`, `Jump`, `Sitting`. Если клипов нет — включи **Import Animation** и **Animation Method → Mecanim**, нажми **Apply**.
2. Меню **Donut Quest → Собрать префаб Корры**.
3. Готовый префаб появится в `Assets/Prefabs/Corra.prefab` и подсветится.
4. Перетащи его в сцену, нажми Play. Корра бегает на A/D или стике.

Что делает сборщик (`Assets/Scripts/Editor/CorraPrefabBuilder.cs`):
- создаёт `CorraAnimator.controller` со состоянием на каждый клип модели;
- собирает корень `Corra` с `CharacterController` + `CorraInput` + `CorraController`;
- внутрь кладёт модель дочерним объектом (`Model`) с `Animator` и `CorraAnimator`.

Модель повёрнута на 180° вокруг Y: glTF — правая система координат, Unity — левая, и без разворота Корра бежала бы задом наперёд. Если всё-таки бежит спиной вперёд, поменяй `ModelYaw` в начале `CorraPrefabBuilder.cs` с 180 на 0 и запусти сборку снова.

## Форматы 3D-моделей для Unity

- **GLB (наш выбор):** один бинарный файл, внутри меш, скелет, анимации и текстуры. В Unity — через пакет `glTFast`. Хорошо лежит в git, не рассыпается на части.
- **glTF:** тот же формат, но разбит на `.gltf` + `.bin` + картинки. Неудобно тащить в репозиторий.
- **FBX:** родной для Unity, но модель на Sketchfab в нём не отдаётся. Конвертировать GLB → FBX можно в Blender, если понадобится.
- **.blend:** файл Blender. Unity импортирует, только если Blender установлен на машине — он запускается в фоне и конвертирует в FBX. Без Blender импорт падает.
- **USDZ:** формат Apple для AR, для игры не нужен.
- **OBJ/MTL:** только статичная геометрия, без костей и анимаций. Для персонажей не годится.

## Как модель подключается к проекту

1. **Файл в репозитории.** `corgi.glb` лежит в `Assets/Models/Corra/`, попадает в git вместе с кодом. Ничего скачивать при клонировании не нужно.
2. **Импорт.** Unity при открытии проекта видит новый файл, ставит пакет `glTFast` из манифеста и импортирует модель: создаёт меш, материал, скелет и три Animation Clip.
3. **Настройка.** В инспекторе модели: Rig → Generic (собака — не гуманоид), Animation → Mecanim.
4. **Сборка префаба.** Меню **Donut Quest → Собрать префаб Корры** делает из модели готового персонажа: физика и скрипты на корне, модель внутри.
5. **В сцене.** Префаб перетаскивается в сцену; `CharacterController` двигает весь объект целиком, включая дочернюю модель.

## Как я проверяю код без Unity (и почему Unity не на сервере)

**Unity Editor на этот сервер не встанет, и это не вопрос настройки.** Проверил:

- Видеокарта — Cirrus Logic GD 5446, это эмуляция без 3D. Unity требует GPU с OpenGL 3.2+ или Vulkan, а также окружение с X11 и драйверами Nvidia/AMD.
- Оперативной памяти 2 ГБ, свободно около 1.1 ГБ. Редактору Unity 6 нужно минимум 8 ГБ, на практике 12–16.
- Диск: свободно 11 ГБ, редактор с модулями занимает 15–20.
- Unity Hub и редактор недоступны из РФ по IP, для лицензии всё равно нужен VPN и вход в аккаунт.

Поэтому запуск редактора, импорт сцены и сборку билда делаешь ты на Windows. А я проверяю то, что можно проверить без редактора.

### Проверка компиляции

```bash
bash tools/compilecheck/check.sh
```

Скрипт компилирует все C#-файлы через Mono, подставляя настоящие сборки `UnityEngine.dll` и `UnityEditor.dll` из пакета `unity3d.sdk` (эталонные сборки Unity, лежат на nuget.org). Что это ловит:

- синтаксические ошибки и опечатки;
- обращения к несуществующим методам и свойствам Unity;
- забытые `using`;
- несовпадение типов при вызове.

Что **не** ловит:

- ошибки времени выполнения (пустой Animator, неверная иерархия объектов);
- различия между версиями Unity — сборки на nuget старее, чем 6.3. Если метод новый, компилятор его не найдёт, хотя в Unity 6.3 он есть. Обратная ситуация опаснее: метод был удалён в Unity 6, а в старых сборках он есть. Такие места я проверяю отдельно, сверяясь с документацией.

Пакет `com.unity.inputsystem` в этих сборках отсутствует, поэтому для него лежат заглушки в `tools/compilecheck/stubs/`. Они повторяют публичный API пакета ровно настолько, насколько его использует наш код. Если начну использовать новые методы — допишу заглушки.

**Проверка в GitHub Actions.** Файл `.github/workflows/compile.yml` запускает тот же скрипт на каждый пуш в `Assets/Scripts`. Красный крестик в репозитории = код не компилируется. Это бесплатно для публичных репозиториев.

### Что можно добавить дальше

- **GameCI** (`game-ci/unity-builder`) — полноценная сборка игры в GitHub Actions с настоящим Unity в контейнере. Требует лицензию Unity: `UNITY_LICENSE`, `UNITY_EMAIL`, `UNITY_PASSWORD` в секретах репозитория. Для Personal-лицензии нужна ручная активация через `.alf`-файл — это делается один раз. Когда аккаунт Unity появится, настроим.
- **Юнит-тесты** игровой логики (подсчёт огурчиков, состояние сохранения) через Unity Test Framework. Они запускаются в GameCI.

## FAQ

**Q:** Почему Input Actions в коде, а не в `.inputactions` ассете?  
**A:** `.inputactions` — это JSON-конфиг, генерирующий C#-обёртку. Код проще видеть в git-диффе и менять через AI. Для больших проектов удобнее ассет, для маленькой игры достаточно кода.

**Q:** Почему в проекте нет URP — разве он не лучше для Steam Deck?  
**A:** URP 17.x (нужный для Unity 6.3) отсутствует в публичном реестре пакетов Unity — я проверил все версии, последняя там 10.10.1, а это URP для Unity 2020. Поэтому проект собран на встроенном рендере. Для low-poly графики с камерой сбоку разница несущественна, а лишняя зависимость только мешает. Если позже понадобится URP (например, для теней в стиле Trine), его подключают через Unity Hub → Window → Package Manager → Unity Registry, там он есть под версию редактора.

**Q:** Как узнать, работает ли Unity Personal?  
**A:** Hub → Settings → Licenses. Если там `Personal`, активна до такой-то даты — всё ок.

**Q:** Можно ли собирать билды на сервере (CI/CD)?  
**A:** Да, Unity поддерживает headless-режим через `batchmode`. Но для первого запуска нужна активация лицензии на машине с UI. Автосборку настроим позже, когда игра заработает локально.

**Q:** Где логи Unity?  
**A:** Unity Editor: **Console** (Window → General → Console).  
Билд игры на Windows: `%APPDATA%\..\LocalLow\Silurus\Donut Quest\Player.log`  
На Linux: `~/.config/unity3d/Silurus/Donut Quest/Player.log`
